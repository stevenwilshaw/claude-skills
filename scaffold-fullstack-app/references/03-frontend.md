# Frontend (`apps/web`)

Vite + React + TypeScript + Tailwind (v4, `@tailwindcss/vite`). No UI framework.

## Packages

- deps: `react react-dom @tanstack/react-router @tanstack/react-query @tanstack/react-form axios @floating-ui/react motion lucide-react react-select clsx zod @app/shared`
- dev: `vite @vitejs/plugin-react tailwindcss @tailwindcss/vite @tanstack/router-plugin @tanstack/react-router-devtools @types/react @types/react-dom typescript vitest jsdom @testing-library/react @testing-library/user-event @testing-library/jest-dom`

`package.json` scripts: `dev: vite`, `build: vite build && tsc --noEmit`, `typecheck: tsc --noEmit`, `test: vitest run`.

**`src/routeTree.gen.ts` does not exist until the router plugin runs** (during `vite dev`/`vite build`), so a fresh scaffold fails typecheck with "cannot find module ./routeTree.gen". After writing the route files, run `npx vite build` once in `apps/web` to generate it (then commit the file). That is also why `build` runs `vite build` before `tsc`. Name `@app/web`, `"type": "module"`.

`tsconfig.json`: extends base, `"jsx": "react-jsx"`, `"lib": ["ES2022","DOM","DOM.Iterable"]`, `"types": ["vite/client", "@testing-library/jest-dom"]`, `"paths": { "@/*": ["./src/*"] }`, `include: ["src", "vite.config.ts", "vitest.config.ts"]`, `noEmit: true`.

## Config

`vite.config.ts` - reads the shared root `.env`, proxies `/api` to the API so the browser sees one origin (cookies just work, no CORS).
```ts
import path from 'node:path';
import tailwindcss from '@tailwindcss/vite';
import { tanstackRouter } from '@tanstack/router-plugin/vite';
import react from '@vitejs/plugin-react';
import { defineConfig, loadEnv } from 'vite';

export default defineConfig(({ mode }) => {
  const rootDir = path.resolve(__dirname, '../..');
  const env = loadEnv(mode, rootDir, '');
  return {
    envDir: rootDir,
    // the router plugin must come before the react plugin
    plugins: [tanstackRouter({ target: 'react', autoCodeSplitting: true }), react(), tailwindcss()],
    resolve: { alias: { '@': path.resolve(__dirname, 'src') } },
    server: {
      port: Number(env.WEB_PORT ?? 5173),
      proxy: { '/api': `http://localhost:${env.PORT ?? 3000}` },
    },
  };
});
```
(Use `import.meta.dirname` instead of `__dirname` in `vite.config.ts` and `vitest.config.ts` - Vite 8's native config loader warns about `__dirname`; `import.meta.dirname` works on Node 22+.)

`vitest.config.ts` - separate from the Vite config so tests do not run the router code generator:
```ts
import path from 'node:path';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vitest/config';

export default defineConfig({
  plugins: [react()],
  resolve: { alias: { '@': path.resolve(__dirname, 'src') } },
  test: { environment: 'jsdom', setupFiles: ['./src/test/setup.ts'], globals: false },
});
```
`src/test/setup.ts` (with `globals: false` Testing Library does not auto-register cleanup, and tests would leak DOM into each other):
```ts
import '@testing-library/jest-dom/vitest';
import { cleanup } from '@testing-library/react';
import { afterEach } from 'vitest';

afterEach(cleanup);
```

`index.html` at the app root with `<div id="root">` and `<script type="module" src="/src/main.tsx">`. `src/index.css`: `@import "tailwindcss";`.

Rule of thumb for placement: a component sits next to the single screen that uses it; if two screens in a feature use it, move it to the feature root; if several features use it, it belongs in `src/components`. Add `*.test.tsx` and (if Storybook) `*.stories.tsx` right next to the component.

## Routes are thin

```tsx
// src/routes/posts/index.tsx
import { createFileRoute } from '@tanstack/react-router';
import { postsQueries } from '@/features/posts/posts.queries';
import { PostsListScreen } from '@/features/posts/list/PostsListScreen';

export const Route = createFileRoute('/posts/')({
  loader: ({ context }) => context.queryClient.ensureQueryData(postsQueries.list()),

```
Same shape for `new`, `$postId/index` (loader prefetches `postsQueries.detail(params.postId)`), `$postId/edit`. `routes/index.tsx` uses `beforeLoad: () => { throw redirect({ to: '/posts' }) }`. ## Data layer - `features/posts/posts.queries.ts`

```ts
import { queryOptions, useMutation, useQueryClient } from '@tanstack/react-query';
import type { CreatePostInput, Post } from '@app/shared';
import { api } from '@/lib/api';

export const postsQueries = {
  all: () => ['posts'] as const,
  list: () =>
    queryOptions({
      queryKey: [...postsQueries.all(), 'list'],
      queryFn: async () => (await api.get<Post[]>('/posts')).data,
    }),
  detail: (id: string) =>
    queryOptions({
      queryKey: [...postsQueries.all(), 'detail', id],
      queryFn: async () => (await api.get<Post>(`/posts/${id}`)).data,
    }),
};

export function useCreatePost() {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: async (input: CreatePostInput) => (await api.post<Post>('/posts', input)).data,
    onSuccess: () => qc.invalidateQueries({ queryKey: postsQueries.all() }),
  });
}
// useUpdatePost({ id, input }) -> PUT, useDeletePost(id) -> DELETE: same shape, same invalidation.
```

### Inputs - know nothing about forms

```tsx
// components/inputs/TextInput.tsx
import clsx from 'clsx';
import type { ComponentProps } from 'react';

export interface TextInputProps extends ComponentProps<'input'> {
  invalid?: boolean;
}

export function TextInput({ invalid, className, ...props }: TextInputProps) {
  return (
    <input
      aria-invalid={invalid || undefined}
      className={clsx(
        'w-full rounded-md border bg-white px-3 py-2 text-sm outline-none transition',
        'focus:ring-2 focus:ring-blue-500 disabled:opacity-60',
        invalid ? 'border-red-500' : 'border-gray-300',
        className,
      )}
      {...props}
    />
  );
}
```
`TextAreaInput` is the same with `<textarea>`.

`SelectInput` wraps react-select, fully styled through Tailwind with `unstyled` + `classNames`:
```tsx
import clsx from 'clsx';
import Select, { type GroupBase, type Props } from 'react-select';

export function SelectInput<
  Option,
  IsMulti extends boolean = false,
  Group extends GroupBase<Option> = GroupBase<Option>,
>(props: Props<Option, IsMulti, Group>) {
  return (
    <Select
      unstyled
      classNames={{
        control: ({ isFocused }) =>
          clsx('rounded-md border bg-white px-2 py-0.5 text-sm', isFocused ? 'border-blue-500 ring-2 ring-blue-500' : 'border-gray-300'),
        menu: () => 'mt-1 rounded-md border border-gray-200 bg-white shadow-lg overflow-hidden',
        option: ({ isFocused, isSelected }) =>
          clsx('px-3 py-2 text-sm cursor-pointer', isSelected ? 'bg-blue-600 text-white' : isFocused && 'bg-gray-100'),
        placeholder: () => 'text-gray-400',
        multiValue: () => 'rounded bg-gray-100 px-1 mr-1',

      {...props}
    />
  );
```

### Fields - TanStack Form glue

```ts

import { createFormHookContexts } from '@tanstack/react-form';
```

```tsx
// components/form/FieldShell.tsx
import type { ReactNode } from 'react';

export function FieldShell({ label, htmlFor, error, children }: { label: string; htmlFor: string; error?: string; children: ReactNode }) {
  return (
    <div className="space-y-1">
      <label htmlFor={htmlFor} className="block text-sm font-medium">{label}</label>
      {children}
      {error && <p role="alert" className="text-sm text-red-600">{error}</p>}
    </div>
  );
}

/** Standard-schema validators (zod) produce `{ message }` objects; plain validators produce strings. */
export const errorMessage = (errors: unknown[]) =>
  errors.map((e) => (typeof e === 'string' ? e : (e as { message?: string })?.message)).filter(Boolean).join(', ') || undefined;
```

```tsx
// components/form/TextField.tsx
import { TextInput, type TextInputProps } from '../inputs/TextInput';
import { errorMessage, FieldShell } from './FieldShell';
import { useFieldContext } from './form-context';

type Props = { label: string } & Omit<TextInputProps, 'value' | 'onChange' | 'onBlur' | 'name' | 'id'>;

export function TextField({ label, ...inputProps }: Props) {
  const field = useFieldContext<string>();
  const error = field.state.meta.isTouched ? errorMessage(field.state.meta.errors) : undefined;
  return (
    <FieldShell label={label} htmlFor={field.name} error={error}>
      <TextInput
        id={field.name}
        name={field.name}
        value={field.state.value}
        onChange={(e) => field.handleChange(e.target.value)}
        onBlur={field.handleBlur}
        invalid={!!error}
        {...inputProps}
      />
    </FieldShell>
  );
}
```
`TextAreaField` identical with `TextAreaInput`. `SelectField<string>` takes `options: { value: string; label: string }[]`, passes `value={options.find(o => o.value === field.state.value)}` and `onChange={(o) => field.handleChange(o!.value)}` to `SelectInput`, `inputId={field.name}`. `SubmitButton` uses `useFormContext()` and `form.Subscribe selector={(s) => [s.canSubmit, s.isSubmitting]}` to disable itself and show a spinner icon (`Loader2` from lucide).

### Button, Popover (floating-ui + motion)

`Button.tsx`: `variant: 'primary' | 'secondary' | 'danger'`, `ComponentProps<'button'>`, Tailwind classes via `clsx`.

```tsx
// components/Popover.tsx
import {
  autoUpdate, flip, FloatingFocusManager, FloatingPortal, offset, shift,
  useClick, useDismiss, useFloating, useInteractions, useRole, type Placement,
} from '@floating-ui/react';
import { AnimatePresence, motion } from 'motion/react';
import { useState, type ReactNode } from 'react';

interface PopoverProps {
  trigger: ReactNode;
  children: ReactNode | ((close: () => void) => ReactNode);
  placement?: Placement;
}

export function Popover({ trigger, children, placement = 'bottom' }: PopoverProps) {
  const [open, setOpen] = useState(false);
  const { refs, floatingStyles, context } = useFloating({
    open,
    onOpenChange: setOpen,
    placement,
    middleware: [offset(8), flip(), shift({ padding: 8 })],
    whileElementsMounted: autoUpdate,
  });
  const { getReferenceProps, getFloatingProps } = useInteractions([useClick(context), useDismiss(context), useRole(context, { role: 'dialog' })]);
  const close = () => setOpen(false);

  return (
    <>
      <span ref={refs.setReference} className="inline-flex" {...getReferenceProps()}>{trigger}</span>
      <FloatingPortal>
        <AnimatePresence>
          {open && (
            <FloatingFocusManager context={context}>
              <div ref={refs.setFloating} style={floatingStyles} className="z-50" {...getFloatingProps()}>
                <motion.div
                  initial={{ opacity: 0, scale: 0.96, y: -4 }}
                  animate={{ opacity: 1, scale: 1, y: 0 }}
                  exit={{ opacity: 0, scale: 0.96, y: -4 }}
                  transition={{ duration: 0.12 }}
                  className="rounded-md border border-gray-200 bg-white p-3 shadow-lg"
                >
                  {typeof children === 'function' ? children(close) : children}
                </motion.div>
              </div>
            </FloatingFocusManager>
          )}
        </AnimatePresence>
      </FloatingPortal>
    </>
  );
}
```
Floating-ui positions the outer div, motion animates the inner one - do not put `transform` animations on the positioned element.

## UI rule: no forms on list pages

A list screen only lists (plus search/filter/sort controls). Never render an add or edit form inline on it - no "new item" form above the table, no rows that turn into editable inputs. Adding and editing happen either on a **separate screen** (its own route: `create/`, `edit/`, as in Posts) or in a **modal** opened from the list. Today the scaffold only uses separate screens; a `Modal` component (`src/components`) is planned, and once it exists a modal is fine for short forms. Either way the form component (`PostForm`) is the same and lives with its feature, so moving a form between a screen and a modal does not change it. Small single-control actions that are not forms (a delete confirmation `Popover`, a status toggle) are fine on the list.

## Screens (what each contains)

- **PostsListScreen**: `useSuspenseQuery(postsQueries.list())` (loader prefetched it), "New post" `Link` with a `Plus` icon, list of `PostListItem` wrapped in motion (`AnimatePresence` + `motion.li layout`), empty state.
- **PostListItem**: title, status badge, description excerpt, links to view/edit.
- **PostViewScreen**: `useSuspenseQuery(postsQueries.detail(id))`, edit link (`Pencil`), delete button inside a `Popover` ("Delete this post?" confirm/cancel) which calls `useDeletePost` and navigates to `/posts`. Uses `Trash2`.
- **PostCreateScreen / PostEditScreen**: `PostForm` + mutation, navigate to the post on success.
- Provide `defaultPendingComponent`/`defaultErrorComponent` on `createRouter` so loaders do not need per-route handling. The error is typed `unknown`: `defaultErrorComponent: ({ error }) => <p role="alert" className="text-red-600">{error instanceof Error ? error.message : String(error)}</p>`.
